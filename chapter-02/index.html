Waking Up the Robot

Part 1 · The Idea

What is a virtual environment?

A virtual environment (venv) is a private, tidy workshop for one project. Instead of dumping every tool onto your Mac's main workbench, you build a separate box that holds exactly the Python version and libraries this robot needs — and nothing else.

Why bother?

  • No clashes. LeRobot needs specific versions. Another project might need different ones. Separate boxes never fight.
  • Reproducible. Delete the box, rebuild it, and you get the exact same setup every time.
  • Safe. You never touch the Python that macOS itself uses.
Analogy: Your Mac is a big kitchen 🍳. A venv is a labeled lunchbox — this project's ingredients live inside it, so they never spoil the rest of the kitchen.

Everything the robot needs lives inside .venv at the root of your project.

Part 2 · The Right Tool

Why Python 3.12 exactly?

Software has version rules. LeRobot's rulebook says: “I need Python 3.12 or newer.” Use something older and it simply won't install.

≥ 3.12Python LeRobot requires
3.12.7Version on this Mac ✅
arm64Apple Silicon chip
Heads up: your Mac ships with an older Python (3.9) for its own use. We must not use that one. We explicitly call python3.12 so the robot gets the version it needs. If you don't have 3.12, install it with brew install python@3.12.

Bonus for Apple Silicon: LeRobot's PyTorch can use the Mac's built-in GPU through a system called MPS (Metal Performance Shaders) — so training and AI models run faster. On this Mac, MPS available: True 🎉

Part 3 · Do It

Set up the environment — step by step

Open the Terminal app on your Mac, go to the project folder, and run these in order. Hit Copy and paste each one.

1

Go to your project folder

cd ~/Documents/robotics
2

Check Python 3.12 is there

python3.12 --version

You should see Python 3.12.7. If not: brew install python@3.12

3

Create the virtual environment

python3.12 -m venv .venv

This builds the .venv lunchbox folder. Do this once.

4

Activate it (do this every time you open Terminal)

source .venv/bin/activate

Your prompt now starts with (.venv) — that's how you know the box is open.

5

Upgrade pip (Python's package installer)

pip install --upgrade pip
6

Install LeRobot with Feetech motor support

pip install -e "./lerobot[feetech]"

The [feetech] part adds the driver for our STS3215 bus servos. This downloads PyTorch too, so it takes a few minutes. ☕

7

Check it worked

lerobot-info

🖥️ Try the terminal — press activate and watch the prompt change

Terminal — robotics
admin@Mac robotics % python3.12 -m venv .venv
admin@Mac robotics % source .venv/bin/activate
Recording datasets later? You'll also want video tools:
brew install ffmpeg && pip install -e "./lerobot[feetech,core_scripts]"
That adds lerobot-record, lerobot-replay and camera/video support. Not needed just to move the motors.
Part 4 · The Wiring

How the kit talks to your Mac

Your Python code doesn't reach the motors by magic. It travels a real path of wires and chips. Press play and watch one command make the trip. 👇

The data path

Python turns your command into bytes → the pyserial library pushes them out the USB-C cable → the green bus servo adapter converts USB into TTL serial (the language Feetech motors speak) → the signal runs down one wire through all 6 motors. Each motor listens only for its own ID (1–6).

Two cables, two jobs

Data (USB-C) is separate from power (the DC barrel jack). USB alone can't supply enough current to lift the arm, so the adapter has its own supply:

ArmPower brick
Follower (does the work)12 V · 2 A
Leader (you hold)5 V · 4 A
Golden rule: the motors get their muscle from the DC power brick, not the USB cable. No power plugged in → the arm goes limp and won't hold position. 🔌
Part 5 · Introductions

“Which cable is which?” — finding the port

Your Mac gives every USB device an address called a port. Since the kit has two arms, you need to learn each one's port name. LeRobot has a clever tool for it.

lerobot-find-port

It lists all ports, asks you to unplug one arm, and sees which address disappeared — that's the arm you unplugged! On a Mac, ports look like /dev/tty.usbmodem575E0032081.

Try the simulator → Click “Unplug the follower” and watch the tool figure out which port vanished, just like the real command does.

You run it twice — once per arm — and write down both ports. You'll paste them into the next commands.

Terminal — lerobot-find-port
(.venv) % lerobot-find-port
Finding all available ports for the MotorBus. ['/dev/tty.usbmodem575E0032081', '/dev/tty.usbmodem575E0031751'] Remove the USB cable from your MotorsBus and press Enter…
Part 6 · Bringing It To Life

The first three commands you'll run

Once the environment is ready and you know the ports, this is the path from “boxes of parts” to “a moving robot.” (We'll go deep on calibration in Chapter 3.)

1 · once per motor

Set motor IDs

Each STS3215 leaves the factory as “ID 1.” This gives them IDs 1–6 so they can share one wire.

lerobot-setup-motors
2 · once per arm

Calibrate

Teach each joint its min and max by moving it by hand, so “90°” means the same thing every time.

lerobot-calibrate
3 · the fun part

Teleoperate

Move the leader arm by hand and the follower copies it in real time. You're driving the robot!

lerobot-teleoperate

Each command needs the port you found (e.g. --robot.port=/dev/tty.usbmodem575E0032081). The full flags are in the LeRobot SO-101 guide — the point for now is the shape of the journey.

🎛️ Want to drive a motor right now? Try the Live Motor Control demo — sliders in your browser move a real STS3215 (or a simulated one if none is plugged in). Start it with python le-robotics/live-demo/motor_bridge.py and open http://localhost:8777.
Wrap-up

Troubleshooting & recap 🎓

❓ “command not found: lerobot-info”

Your venv isn't active. Run source .venv/bin/activate first — you should see (.venv) in the prompt.

❓ “No module named lerobot”

Same fix — activate the venv, or the install (step 6) didn't finish. Re-run pip install -e "./lerobot[feetech]".

❓ The arm is limp / motors won't hold

The DC power brick isn't plugged into the bus adapter. USB carries data, not muscle.

❓ find-port shows nothing

Check the USB-C cable is a data cable (some are charge-only), and try a different port. On Linux you may need sudo chmod 666 /dev/ttyACM0; on Mac this usually isn't needed.

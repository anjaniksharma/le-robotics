Calibration:
Teaching Both Arms Where They Are

A motor only knows a raw number from 0 to 4095 — it has no idea what "straight up" or "90°" means. Calibration is how we teach each joint its center and its limits, so both the leader and follower speak the exact same language. Do this once, and the two arms can finally work together.

Part 1 · The Problem

Why do we calibrate?

Remember from Chapter 1: each STS3215 has a 12-bit encoder giving a raw count of 0–4095 per turn. But that raw number is arbitrary — where it lands depends on exactly how the horn was screwed on when the arm was built. On your follower, "elbow straight" might read 2130; on my follower it might read 1980.

That's a disaster for two reasons:

  • Teleoperation: the leader tells the follower "go to 2130" — but on the follower that's a totally different pose. The arms wouldn't match.
  • Learning: a neural network trained on one robot would be useless on another.
Analogy — tuning two guitars 🎸: before two people can play a song together, both guitars must be tuned to the same pitch. Calibration "tunes" both arms to the same reference so a command means the same thing on each.

Part 2 · The Idea

Calibration = four numbers per motor

Calibrating a joint just means measuring and saving four values. LeRobot stores these for all six motors:

🎯 homing_offset

The correction that makes the joint's middle read as the standard center (count 2048). This defines where 0° is.

📏 range_min

The smallest raw count the joint can physically reach — one end of its travel.

📏 range_max

The largest raw count it can reach — the other end. Together with range_min this maps the joint to a tidy −100…100 (or 0…100 for the gripper).

🔄 drive_mode

Which way is "positive." If a joint's counts go down as it moves the direction we call positive, drive_mode flips it so up is always up.

You'll gather these in two hands-on steps: first set the center, then record the range. Let's do each. 👇
Part 3 · Step 1

Set the center (half-turn homing)

First you move every joint to the middle of its range — roughly the pose where the arm stands neutral — and press Enter.

LeRobot reads each motor's raw count right then and computes:

homing_offset = present − 2048

From now on the software subtracts that offset, so this "middle" pose reads exactly 2048 → 0°. Same physical pose, same number, on every arm.

Try it → Drag to a pose you'll call "the middle," then press Set center. Watch the calibrated readout snap to 0°, and see it stay meaningful as you move.

Part 4 · Step 2

Record the range of motion

Next, LeRobot turns the motors' torque off so you can move them freely by hand. You wiggle each joint from one hard stop to the other while it watches the live count, keeping track of the smallest (MIN) and largest (MAX) it sees. Press Enter when done.

The real console prints a live table exactly like this:

recording ranges
NAME | MIN | POS | MAX elbow_flex | 2130 | 2130 | 2130
Cover the whole range! If you don't push a joint all the way to both stops, the robot will think its limits are narrower than they really are.

Part 5 · Do It For Real

Calibrate both arms

You run the same two-step process (center, then range) on each arm — but the commands differ, because the follower is a robot and the leader is a teleoperator. Give each a unique id so its calibration is saved and reused.

The follower is the arm that does the work. It's a robot, so it uses --robot.* flags:

lerobot-calibrate --robot.type=so101_follower --robot.port=/dev/tty.usbmodem58760431551 --robot.id=my_follower_arm

The leader is the arm you move by hand to drive the follower. It's a teleoperator, so it uses --teleop.* flags:

lerobot-calibrate --teleop.type=so101_leader --teleop.port=/dev/tty.usbmodem575E0031751 --teleop.id=my_leader_arm
Terminal — lerobot-calibrate
Press ▶ to walk through a calibration run.
Use the port you found in Chapter 2. Plug each arm's own /dev/tty.usbmodem… port into its command. Don't forget: motor IDs must already be set with lerobot-setup-motors before you calibrate.
Part 6 · Saved For Good

Where calibration lives

When you finish, LeRobot writes those four-numbers-per-motor to a small JSON file, named after the arm's id. It also writes the homing offset into the motor's own memory.

~/.cache/huggingface/lerobot/calibration/robots/so101_follower/my_follower_arm.json
~/.cache/huggingface/lerobot/calibration/teleoperators/so101_leader/my_leader_arm.json

Because it's keyed by id, every future lerobot-teleoperate or lerobot-record command loads it automatically. You calibrate once per arm (until you rebuild or re-mount a motor).

Inside the JSON (one motor)

"elbow_flex": { "id": 3, "drive_mode": 0, "homing_offset": 82, "range_min": 812, "range_max": 3140 }

Six of these little blocks = a fully-calibrated arm. Human-readable, and you can back it up.

Part 7 · The Payoff

Now the two arms can dance 🤝

With both arms calibrated to the same reference, teleoperation finally works: move the leader, and the follower copies it — because "elbow at 30°" now means the same physical thing on both.

The follower mirrors it instantly — that's the whole game. 🎯

lerobot-teleoperate --robot.type=so101_follower --robot.port=/dev/tty.usbmodemFOLLOWER --robot.id=my_follower_arm --teleop.type=so101_leader --teleop.port=/dev/tty.usbmodemLEADER --teleop.id=my_leader_arm

One command names both calibrated arms by their ids. LeRobot loads each calibration, reads the leader's joints, and writes them to the follower — many times a second.

🔎 Bonus: what is “drive_mode” really doing?

Two motors mounted facing opposite directions will count in opposite directions for the same physical motion. drive_mode flips the sign for such joints so that "positive" always means the same real-world direction across the whole arm — and across every arm. It's the reason your calibrated angles are consistent even when motors are mounted mirror-image.
